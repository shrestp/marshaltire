## What works
- **Hero slider:** autoplay, pause, previous/next, dots and swipe.
- **Tire finder:** By Vehicle / By Size tabs. A size search opens the Tire Details size chart already filtered.
- **Tire Details:** size accordions grouped by rim size, a size filter with highlighting, horizontally scrolling spec tables and a CSV download. All 25 MF41 sizes come from MS_Spec.xlsx.
- **Dealer Finder:** you can search by ZIP or city, or use your location. Results are sorted by distance (15-mile radius) on an OpenStreetMap map.
- **Shop online (Dealer Finder page):** pick a tire, then a retailer; the retailer's site opens in a new tab with that tire searched.
- **Contact:** Drivers and Business tabs, plus conditional warranty fields. The form validates input and shows a success state.
- **Layout:** works on desktop and mobile, and includes a mobile menu.

## What's placeholder
- The dealers are 8 sample Colorado locations.
- The contact form doesn't send anything.
- Highway Terrain, Tour A/S and Sport A/S have no size/spec data yet: their size section is a "coming soon" placeholder, they have one product photo each and no Applied Technology section.
- The Discount Tire and Tire Rack search-link formats are unconfirmed (set in `RETAILERS` in `assets/js/main.js`).
- Pages for Warranty, Privacy and the other footer links show a "not part of this mockup" notice.

## Run locally
```
python3 -m http.server 8000
```
Then open http://localhost:8000.

## Publish (GitHub Pages)
Go to Settings → Pages, set Source to "Deploy from a branch", then choose Branch `main` and folder `/ (root)`.

## Editing pages
The page markup is generated by `build/pages.py`. Edit that file and run `python3 build/pages.py`. Shared styles are in `assets/css/styles.css`, and the behaviour is in `assets/js/main.js`.

## Client feedback
Every page has a **Feedback** button (bottom right). A reviewer clicks **Add a note**, clicks any spot on the page and leaves a note with their name. Pins follow the element they were placed on, so they stay put on desktop and mobile. All notes are listed on `review.html`, where you can view each one on its page, mark it resolved, delete it or download a CSV.

Until Supabase is connected the widget runs in demo mode: notes are saved only in the reviewer's own browser.

### Connect Supabase (free plan)
1. Create a project at supabase.com.
2. Open **SQL Editor** and run:
   ```sql
   create table feedback (
     id uuid primary key default gen_random_uuid(),
     created_at timestamptz not null default now(),
     page text not null, anchor text, ax real, ay real, x real, y real, vw int,
     author text, body text not null check (char_length(body) <= 2000),
     status text not null default 'open'
   );
   alter table feedback enable row level security;
   create policy "anyone reads"   on feedback for select using (true);
   create policy "anyone adds"    on feedback for insert with check (true);
   create policy "anyone updates" on feedback for update using (true);
   create policy "anyone deletes" on feedback for delete using (true);
   ```
3. In **Project Settings → API**, copy the Project URL and the `anon` public key into `assets/js/feedback-config.js`.

The anon key is meant to be public. Anyone with the site link can read, resolve or delete notes, which is fine for a private mockup link. Free projects pause after a week with no activity; restore them from the Supabase dashboard.
